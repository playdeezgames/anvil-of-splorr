# World editor: specification (as agreed so far)

**Hub**: the world editor's start screen has three sections, LOOK (palette, tile size, tilesets, terrain sets, sprite sets), RULES (tags, parameters, sounds) and ACTORS (character types, characters, maps). The top level shows each with counts (RULES also how many needed tags are missing); green opens one, red goes up a level (red at the top leaves the editor), yellow plays and blue opens the file screen at both levels. The "hub" rows named below live inside these sections.

A world is a collection of asset types; more types will be added later. Everything below is saved in one file, `world.json` (format documented in `common/world.odin`).

- **Tile size**: one for the whole world, 1..64 by 1..64 (default 16x16). Every tileset must match it. Changing it crops or pads every image in every tileset (hidden pixels return when growing back).
- **Palette**: exactly one, 16 colours, an embedded copy edited inside the world editor.
- **Tilesets**: up to 16, each named. Embedded copies edited with the tileset editor's screens (width and height are the world's, so they are not offered). A tileset can be imported from `tileset.json` if its tile size matches the world's (otherwise refused with a message). A tileset cannot be deleted while a terrain uses it; renaming a tileset or an image updates the terrains that use it; an image used by a terrain cannot be deleted.
- **Tags**: one world-wide list of up to 64 named tags, edited from the TAGS row of the hub (new, rename, delete). Tag 0 is `solid`: it always exists and cannot be renamed or deleted, since game code looks for it by name. Terrains and character types (the "types") have a tag or do not. Characters and map cells (the "instances") have three states per tag: inherit from their type (a character's character type, a cell's terrain), set, or cleared; green on a tag cycles inherit, set, cleared. The terrain, character type, character and map editors each have a Tags screen (Setup row and TAGS button; in the map editor it is the cell under the cursor, or the current character on the Characters layer). Deleting a tag asks for a second press, says how many things use it, and clears it everywhere. In `world.json` the list is `tags` ("solid" first), things list their set tags by name, instances also `tags_cleared`, and a map's own cell settings are `cell_tags`. Old files with a terrain `"solid": true` load as the tag.
- **Tags the game needs**: a game can ship a hand-edited `game_tags.json` (`{"tags": [{"name": "thing", "note": "what the player picks up"}, "spawn"]}`; each tag is an object with an optional one-line note up to 80 characters, or just a name). The world editor reads it from the working directory (native) or from beside the page or browser storage (web; the page's "Open file" button also takes it) when it opens and each time the TAGS list opens. The list then shows each needed tag as NEEDED, NEEDED UNUSED (the world has it but nothing sets it) or, as a row of its own, MISSING; the info line shows the game's note; CREATE adds every missing tag at once; renaming or deleting a needed tag asks a second time (the game looks tags up by name). `anvil_runtime.required_missing` is the same check for a game at start-up.
- **Game parameters**: named values a game reads instead of hard-coding: up to 64, each a whole number (32-bit range) or a short text (up to 32 printable ASCII characters, empty allowed), names unique, 1..32 printable ASCII. Edited from the PARAMS row of the hub: the list has new, duplicate, rename, delete (twice) and KIND (number or text; the other value is kept), and a parameter opens a value screen: left/right change a number by 1, up/down by 10, the wheel by 1, buttons -10 -1 +1 +10, and green types the value with the keypad (a bad number asks again). In `world.json`: `"params": [ {"name": "round_seconds", "number": 60}, {"name": "title", "text": "Go Get It"} ]`, optional on load. A game reads them with `anvil_runtime.param_number(w, name, default)` and `param_text(w, name, default)`.
- **Sounds**: up to 64 named sounds, each a name (unique, 1..32 printable ASCII), a text of up to 1024 printable ASCII characters in the style of BASIC's `PLAY` (see `SOUND.md`; empty is allowed, and the text is checked by the PLAY parser, not by the world) and a `loop` setting. In `world.json`: `"sounds": [ {"name": "pickup", "text": "T200 O5 L16 C E G >C", "loop": false} ]`, optional on load (`text` and `loop` are optional too). The model is `common/world_sounds.odin`. In the world editor the SOUNDS row is in the RULES section: a list like the others (new, duplicate, rename, delete) and a sound screen: green plays it from the start (on channel 0 of the frontend's mixer, looping if `loop`), blue stops it, yellow types the text with the long keypad (up to 1024 characters; the field shows the end of the text), left/right switch looping, red goes back; the screen shows the length and note count or the error with its character marked. Text with a PLAY error can be stored but does not play. A game plays one with `anvil_runtime.sound_play(w, name, channel)` (see GAMES.md).
- **Play** (a try-out, not a game): YELLOW in the hub (or the PLAY button) walks the world's player around its map. One step per press of the four direction commands (or a click on a neighbouring cell), blocked by `solid` cells (the effective tag, so a cell's own setting counts), the map's edge and other characters; the message strip says why. The whole map is shown at the largest whole-number zoom that fits, else a window follows the player. Red or BACK returns to the hub; the play state is separate from the world, so the authored positions are never changed. It needs a player standing on a map (otherwise the hub says so).
- **Terrain sets**: up to 16, each named. A set has 1..256 terrains and a default terrain (new sets start with one terrain, "terrain"). A terrain has a name (unique within its set), tags (the "solid" flag is the tag `solid`; see Tags) and a reference by name to a tileset and an image in it (a new terrain points at the first image of the first tileset, or is "not set" and shown in red). A terrain cannot be deleted while it is the default, while it is the last one, or while map cells use it. Terrains are not reordered. A set cannot be deleted while a map uses it.
- **Sprite sets**: up to 16, each named, each holding 0..256 named sprites (unique within the set). A sprite is a tile (a tileset and an image in it, by name, shown red while not set) with a transparent colour index 0..15 or none (default 0) that is not drawn. Character types, feature types and item types draw sprites, so a sprite or sprite set one of them draws cannot be deleted, and a tileset or image a sprite uses is protected like terrains' are. The sprite editor shows sprites over a checkerboard, or over a terrain chosen as a background (not saved).
- **Character types**: up to 64 in the world, each named (unique) with a sprite (a sprite set and a sprite in it, by name; shown red while not set). A type cannot be deleted while a character has it, and the sprites and sprite sets types draw cannot be deleted either; renames follow. The type editor shows each over a checkerboard or a chosen terrain.
- **Characters**: one world-level table of up to 1024, each with a uuid (random version 4, made once, never changed), a name (a label, not unique) and a character type. A map cell holds a character's uuid or nothing; the world's optional **player** is a uuid too. A character stands in at most one cell of the whole world, or on no map. Placing a placed character moves it; placing onto a taken cell is refused. Deleting a character takes it off its map and clears the player if it was the player. A map cannot shrink over a character, flips and rotations carry characters with their cells, and deleting a map only takes its characters off (they stay in the table). Characters are edited in their own editor (a list: rename, new, duplicate, delete, type, player, unplace) and from the map editor's Characters layer (green places or picks, the Setup rows do the same things); both show the same table.
- **Feature types and features** (see `FEATURES.md`; built: the model, the file, the editors, the map editor layer, the runtime and the MCP tools): features are things that stand in a cell and never move (a tree, a door, a sign). A feature type (up to 64, unique names) has a sprite (a sprite set and a sprite, shown red while not set) and tags; a feature (up to 2048, one table for the world) has a uuid (random version 4, shared generator with characters, never reused), a name (a label, not unique), a type and its own tag settings (inherit / set / cleared, as for characters). A map cell holds a feature's uuid or nothing: **one feature a cell**, and a feature stands in at most one cell of the whole world. **A feature always blocks**: a cell cannot hold a feature and a character together (placing either is refused, as is loading a file with both). A type cannot be deleted while a feature has it, the sprites and sprite sets types draw are protected, renames follow, deleting a feature takes it off its map, a map cannot shrink over a feature, flips and rotations carry features, and a duplicated map starts with no characters or features. In `world.json`: `"feature_types": [ {"name", "sprite_set", "sprite", "tags"} ]`, `"features": [ {"uuid", "name", "type", "tags", "tags_cleared"} ]` and in each map `"features": [ {"x", "y", "feature"} ]`, all optional on load.
- **Editing feature types and features**: in the world editor's ACTORS section the rows FEATURE TYPES and FEATURES open the feature type editor (names, sprite set and sprite, tags, a checkerboard or terrain backdrop; copies the character type editor) and the feature editor (a list of features: rename, new, duplicate, delete (twice), type, unplace, tags; copies the character editor without the player). A feature type cannot be deleted while features have it.
- **Features in the map editor**: a third layer, FEATURES, after TERRAIN and CHARACTERS (the LAYER button or Setup row cycles terrain, characters, features). Green puts the current feature in a free cell (moving it from where it stood) or picks the feature already there; a cell with a character refuses it (and the Characters layer refuses a cell with a feature). Setup rows: Feature, Type, Rename, New, Unplace, Delete (twice), Zoom, Layer, Tags; the picker shows 16 features a page; right click picks. Drawing order: terrain, then features, then characters.
- **Item types, inventories and numeric properties** (built: the model, the file, the editors, the map editor layer, the runtime and the MCP tools): items exist only inside **inventories**. An **item type** (up to 128, unique names) has a sprite (a sprite set and a sprite, shown red while not set), tags, a **max stack** (1 = unique items that never stack, like a sword; more = counted items, like gold; up to 1,000,000,000) and up to 16 **numeric properties** (a `Prop_Set`, `common/prop_set.odin`: a unique name and a default, whole numbers that fit in 32 bits; the one place the world stores numbers beside tags, written to be reused by characters and features later). An **entry** is `{item type, count, property overrides}` with no identity of its own: a stack of one is a unique item whose own values (a durability of 40) are overrides of the type's defaults; an override equal to the default is not kept, entries merge only when the type and every property value are equal and never beyond the max stack. An **inventory** (a uuid and its entries, in order) belongs to exactly one **owner**: a character, a feature or a map cell (up to 1024 inventories, 256 entries in one, 8192 entries in the world). The owner holds the inventory's uuid (`Character.inventory`, `Feature.inventory`, `World_Map.inventories`); **an inventory that runs empty removes itself** and its owner has none; inventories never block and take no part in the one-per-cell rule. Deleting a character, feature or map deletes what it held, a copy of a character, feature or map holds nothing, a map cannot shrink over a cell that holds items (`THINGS IN THE WAY`), flips and rotations carry cell inventories, an item type cannot be deleted while an entry has it, lowering a max stack is refused while an entry holds more, and sprites and sprite sets item types draw are protected like those of the other types. In `world.json`: `"item_types": [ {"name", "sprite_set", "sprite", "tags", "max_stack", "props": [ {"name", "value"} ]} ]` and `"inventories": [ {"uuid", "owner": {"kind": "character"|"feature", "uuid"} | {"kind": "cell", "map", "x", "y"}, "entries": [ {"type", "count", "props": {"durability": 40}} ]} ]`, both optional on load; an inventory with no entries, a missing owner or an owner with two inventories is an error.
- **Editing item types and inventories**: the ACTORS row ITEM TYPES opens the item type editor (a copy of the feature type editor: name, sprite, tags, a STACK row with -/+ and the keypad, and a PROPS screen: a list of properties, left/right change a default by 1, green types it, yellow renames, blue then green deletes, the NEW row adds). The **inventory screen** (`inventory_editor`, hosted by the world editor as `Mode.Inventory`) lists an owner's entries: left/right change the count by 1, yellow types it, green opens the entry's properties (left/right change that entry's value, green types it, yellow puts back the type's default) or, on the last row, picks an item type to add (it joins a matching stack), blue then green deletes an entry. It opens from the ITEMS button of the character editor and the feature editor, and from the map editor's Items layer.
- **Items in the map editor**: a fourth layer, ITEMS, after TERRAIN, CHARACTERS and FEATURES. Green (or a click) on a cell opens that cell's inventory screen; Setup rows Open, Clear (twice), Zoom, Layer (no tags: an inventory has none); the area where the picker is lists the cell's entries. Every layer draws a cell's inventory as its first entry's sprite: terrain, then inventories, then features, then characters.
- **Maps**: up to 64, each named, 1..64 columns by 1..64 rows (default 32x32), using one terrain set. Cells hold a terrain (by name in the file). New and newly exposed cells take the set's default terrain. A map can move to another terrain set only if every cell's terrain exists by name in the new set. The map editor follows the image editor: paint, flip, rotate (square maps only), frame and filled rectangles, flood fill, replace terrain, clear.
- **Names**: 1..32 printable ASCII characters, unique within their own list, typed with the keypad.
- **Open question**: file size of a world full of big tilesets (settled for games by `WEB_FILE_MIB`, `#load` and `WEB_FETCH`; see `FILE_CAP` in `frontends/web/web.odin`).

- **Features and collisions at run time** (`anvil_runtime`): features have positions in the `Play_State` like characters (`play_feature_position/_at`, `play_features_in_map`, `play_place_feature`, `play_unplace_feature`), always block (`Move_Result.Feature`), draw with `draw_features` before `draw_characters`, and the world editor's Play mode shows them and says `BLOCKED BY <name>`. `play_step` queues a `Collision` (mover, Character or Feature, the other's index, map, cell, step) whenever a character is refused by another character or a feature; a game drains them with `play_take_collision` and decides from tags what happens (open the door, start the fight). Walls and map edges are not collisions.
- **Items at run time** (`anvil_runtime/items.odin`): item types are asked as authored (`find_item_type`, `item_type_max_stack/_sprite/_image/_has_tag`, `item_prop_index/_default`); `play_init` copies the authored inventories into the `Play_State`, whose `Owner` is a character or feature index or a map cell (`owner_character/_feature/_cell`). A game changes inventories only there: `play_add_item`, `play_remove_item`, `play_transfer` (one entry at a time, keeps the property values, moves only what fits), `play_transfer_all`, `play_drop`, `play_split`, `play_merge`, `play_set_entry_value`, `play_clear_items`, and looks with `play_entry_count/_entry/_entry_value`, `play_cell_has_items`, `play_cells_with_items`. Stepping onto a cell that holds an inventory is **never refused**: `play_step` queues a `Contact` (`play_take_contact`, `play_clear_contacts`, 64, oldest dropped, `contacts_lost`) and the game decides (pick it up with `play_transfer_all`, ignore it). `draw_inventories` draws the first entry's sprite of each cell, before `draw_features`. The world editor's Play mode draws them and says `HERE: 25 gold`. The `Play_State` is about 0.9 MB now (most of it the entries): a global or `new()`.
