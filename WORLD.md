# World editor: specification (as agreed so far)

**Hub**: the world editor's start screen has three sections, LOOK (palette, tile size, tilesets, terrain sets, sprite sets), RULES (tags, parameters) and ACTORS (character types, characters, maps). The top level shows each with counts (RULES also how many needed tags are missing); green opens one, red goes up a level (red at the top leaves the editor), yellow plays and blue opens the file screen at both levels. The "hub" rows named below live inside these sections.

A world is a collection of asset types; more types will be added later. Everything below is saved in one file, `world.json` (format documented in `common/world.odin`).

- **Tile size**: one for the whole world, 1..64 by 1..64 (default 16x16). Every tileset must match it. Changing it crops or pads every image in every tileset (hidden pixels return when growing back).
- **Palette**: exactly one, 16 colours, an embedded copy edited inside the world editor.
- **Tilesets**: up to 16, each named. Embedded copies edited with the tileset editor's screens (width and height are the world's, so they are not offered). A tileset can be imported from `tileset.json` if its tile size matches the world's (otherwise refused with a message). A tileset cannot be deleted while a terrain uses it; renaming a tileset or an image updates the terrains that use it; an image used by a terrain cannot be deleted.
- **Tags**: one world-wide list of up to 64 named tags, edited from the TAGS row of the hub (new, rename, delete). Tag 0 is `solid`: it always exists and cannot be renamed or deleted, since game code looks for it by name. Terrains and character types (the "types") have a tag or do not. Characters and map cells (the "instances") have three states per tag: inherit from their type (a character's character type, a cell's terrain), set, or cleared; green on a tag cycles inherit, set, cleared. The terrain, character type, character and map editors each have a Tags screen (Setup row and TAGS button; in the map editor it is the cell under the cursor, or the current character on the Characters layer). Deleting a tag asks for a second press, says how many things use it, and clears it everywhere. In `world.json` the list is `tags` ("solid" first), things list their set tags by name, instances also `tags_cleared`, and a map's own cell settings are `cell_tags`. Old files with a terrain `"solid": true` load as the tag.
- **Tags the game needs**: a game can ship a hand-edited `game_tags.json` (`{"tags": [{"name": "thing", "note": "what the player picks up"}, "spawn"]}`; each tag is an object with an optional one-line note up to 80 characters, or just a name). The world editor reads it from the working directory (native) or from beside the page or browser storage (web; the page's "Open file" button also takes it) when it opens and each time the TAGS list opens. The list then shows each needed tag as NEEDED, NEEDED UNUSED (the world has it but nothing sets it) or, as a row of its own, MISSING; the info line shows the game's note; CREATE adds every missing tag at once; renaming or deleting a needed tag asks a second time (the game looks tags up by name). `anvil_runtime.required_missing` is the same check for a game at start-up.
- **Game parameters**: named values a game reads instead of hard-coding: up to 64, each a whole number (32-bit range) or a short text (up to 32 printable ASCII characters, empty allowed), names unique, 1..32 printable ASCII. Edited from the PARAMS row of the hub: the list has new, duplicate, rename, delete (twice) and KIND (number or text; the other value is kept), and a parameter opens a value screen: left/right change a number by 1, up/down by 10, the wheel by 1, buttons -10 -1 +1 +10, and green types the value with the keypad (a bad number asks again). In `world.json`: `"params": [ {"name": "round_seconds", "number": 60}, {"name": "title", "text": "Go Get It"} ]`, optional on load. A game reads them with `anvil_runtime.param_number(w, name, default)` and `param_text(w, name, default)`.
- **Play** (a try-out, not a game): YELLOW in the hub (or the PLAY button) walks the world's player around its map. One step per press of the four direction commands (or a click on a neighbouring cell), blocked by `solid` cells (the effective tag, so a cell's own setting counts), the map's edge and other characters; the message strip says why. The whole map is shown at the largest whole-number zoom that fits, else a window follows the player. Red or BACK returns to the hub; the play state is separate from the world, so the authored positions are never changed. It needs a player standing on a map (otherwise the hub says so).
- **Terrain sets**: up to 16, each named. A set has 1..256 terrains and a default terrain (new sets start with one terrain, "terrain"). A terrain has a name (unique within its set), tags (the "solid" flag is the tag `solid`; see Tags) and a reference by name to a tileset and an image in it (a new terrain points at the first image of the first tileset, or is "not set" and shown in red). A terrain cannot be deleted while it is the default, while it is the last one, or while map cells use it. Terrains are not reordered. A set cannot be deleted while a map uses it.
- **Sprite sets**: up to 16, each named, each holding 0..256 named sprites (unique within the set). A sprite is a tile (a tileset and an image in it, by name, shown red while not set) with a transparent colour index 0..15 or none (default 0) that is not drawn. Sprites are for items, features and creatures, to be added later; nothing places them yet, so sprite sets and sprites can be deleted freely, but a tileset or image a sprite uses is protected like terrains' are. The sprite editor shows sprites over a checkerboard, or over a terrain chosen as a background (not saved).
- **Character types**: up to 64 in the world, each named (unique) with a sprite (a sprite set and a sprite in it, by name; shown red while not set). A type cannot be deleted while a character has it, and the sprites and sprite sets types draw cannot be deleted either; renames follow. The type editor shows each over a checkerboard or a chosen terrain.
- **Characters**: one world-level table of up to 1024, each with a uuid (random version 4, made once, never changed), a name (a label, not unique) and a character type. A map cell holds a character's uuid or nothing; the world's optional **player** is a uuid too. A character stands in at most one cell of the whole world, or on no map. Placing a placed character moves it; placing onto a taken cell is refused. Deleting a character takes it off its map and clears the player if it was the player. A map cannot shrink over a character, flips and rotations carry characters with their cells, and deleting a map only takes its characters off (they stay in the table). Characters are edited in their own editor (a list: rename, new, duplicate, delete, type, player, unplace) and from the map editor's Characters layer (green places or picks, the Setup rows do the same things); both show the same table.
- **Maps**: up to 64, each named, 1..64 columns by 1..64 rows (default 32x32), using one terrain set. Cells hold a terrain (by name in the file). New and newly exposed cells take the set's default terrain. A map can move to another terrain set only if every cell's terrain exists by name in the new set. The map editor follows the image editor: paint, flip, rotate (square maps only), frame and filled rectangles, flood fill, replace terrain, clear.
- **Names**: 1..32 printable ASCII characters, unique within their own list, typed with the keypad.
- **Open question**: file size of a world full of big tilesets (see `BACKLOG.md`).
